# Project Bridge: Ethics, Safety, and Governance Policy

---

## 1. Clinical Scope & Non-Diagnostic Boundaries
- **No Diagnosis or Triage:** Project Bridge is an administrative and navigation intake assistant. It explicitly does **not** diagnose medical conditions, explain physiological causes, prescribe medications, recommend treatments, or provide clinical triage.
- **Simulated Actions Only:** Intake records created by the prototype (`BRG-H-2026-XXXXX`) are in-memory simulations designed for demonstration and architectural validation. No real clinics, hospital dispatchers, or electronic medical record (EMR) systems are contacted.
- **Human Oversight Requirement:** All summaries generated by Project Bridge are structured drafts intended solely for review by qualified human healthcare professionals.

---

## 2. Emergency Safety Escalation
- **Narrow Deterministic Emergency Escalation Boundary:** The system monitors user input for explicit, documented life-threatening language:
  - Severe difficulty breathing (*"cannot breathe"*, *"mi ò lè mí"*)
  - Unconsciousness or unresponsive states
  - Uncontrolled bleeding
  - Active seizures
  - Explicit life-threatening emergency statements
- **Immediate Escalation:** When an emergency trigger is detected, the routine intake process halts immediately. No intake proposal is generated; instead, the user is directed to seek immediate local emergency medical assistance.
- **Scope Limitation:** The emergency filter is a narrow deterministic emergency escalation boundary, not a comprehensive or validated clinical triage engine.

---

## 3. Privacy, Data Minimization & Sensitive Health Text
- **Health Text Sensitivity:** Health-related statements represent sensitive personal information. Project Bridge treats all user utterances as private and transient.
- **Minimal Data Collection:** 
  - The system asks only for an **optional preferred first name or nickname** (e.g., *"Tomiwa"* or *"Auntie Kemi"*) so clinicians know how to address the person.
  - The system rejects or redacts unnecessary sensitive identifiers (e.g., national identification numbers, credit card details, full government names).
  - The preferred name step is skippable and does not gate intake generation.
- **Audio Transience & Third-Party Disclosure:**
  - Project Bridge does **not** persist raw product audio. Audio buffers exist only in browser memory and transient API request memory during transcription.
  - Users are informed that audio is transmitted securely to the configured speech provider (e.g., Intron/Sahara) for transcription processing.

---

## 4. User Agency & Explicit Confirmation
- **User-in-the-Loop Transcript Review:** Users are presented with an editable transcript immediately after speech recognition, ensuring they retain full authority to correct misheard words before downstream processing.
- **Explicit Confirmation Gate:** Consequential state changes (such as generating an intake reference) require affirmative user confirmation after reviewing a structured summary of their stated facts.

---

## 5. Benchmark Governance & Licensing
- **Vocal Money Dataset (`CC-BY-NC-SA-4.0`):** The development benchmark utilizes a public AfriSwitch derivative dataset published under Creative Commons Attribution-NonCommercial-ShareAlike 4.0.
- **Governance Notices:** The dataset card states that original speakers did not consent specifically to secondary derivative publishing. Project Bridge isolates benchmark evaluation to secondary development evidence only, holds uncertain audio clips ($N=3$), and marks official primary dataset access (`intronhealth/AfriSwitch`) as awaiting full governance approval.
- **Separation of Fixtures:** The 16 synthetic healthcare evaluation fixtures are authored in TypeScript; they contain no collected participant data, real patient audio, or unverified clinical results.

---

## 6. Linguistic Inclusion & Accessibility
- **Code-Switching Support:** By actively supporting Yoruba-English code-switching and Nigerian Pidgin phrasing, Project Bridge reduces linguistic discrimination against users who do not communicate in formal monolingual English.
- **Multimodal Accessibility:** The interface provides both voice recording and manual keyboard text entry, ensuring access for users with varying physical, vocal, or connectivity needs.
